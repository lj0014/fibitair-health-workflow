# 从零搭建：把自己的健康数据接到 ChatGPT

本文对应 `src/workflow/worker.ts`，按 Windows PowerShell 编写。macOS / Linux 用户请先看 [MCP 搭建与改动说明](MCP搭建与改动.md)。建议先读 [方案原理与架构](方案原理与架构.md)，再按顺序操作。以下 `YOUR-WORKER`、`YOUR-SUBDOMAIN` 均为占位符，必须换成你自己的部署地址。示例日程为合成数据。

复现目标是：你提问时，ChatGPT 调用工具，从 Google Health 读取此刻已有的数据、归档并返回；平时定时补齐历史，按需给自己的 Gmail 发周度数据包。手环/手机上传、Google API 可访问性、ChatGPT 工具可用性分别验收，服务部署成功不能替代这些验收。

## 1. 准备账号、设备和环境

| 必备项 | 你需要完成的事 | 完成标准 |
|---|---|---|
| 设备及手机 | 设备关联 Google Health，手机正常同步 | 手机中能看到自己的活动/睡眠等记录；并非所有型号都会产生所有指标 |
| Google Cloud | 创建自己控制的项目，确认可启用 Google Health API | 按 [Google 官方设置指南](https://developers.google.com/health/setup) 核对当前准入条件；若控制台未提供 API，先解决资格/项目问题 |
| Cloudflare | 注册账号、能创建 Workers、KV、D1 | 登录后可操作自己的账号；不需要先购买套餐 |
| Gmail（可选） | 自己控制且允许授权的 Gmail | 仅需要周邮件时配置；关闭周邮件时可跳过 Gmail 授权 |
| ChatGPT | 账号/工作区允许添加并使用自定义 MCP 工具 | 以自己的界面和管理员权限为准；手机端还需另行确认工具可用 |
| 本地环境 | Git、Node.js、pnpm | 源码要求 Node ≥22.13；本项目搭建环境记录为 Node 24.15.0，包管理器锁定 pnpm 10.30.0 |

本项目只说明已实现的 Google Health v4 路径，不保证任意设备、账号、地区都能读到数据。设备产数、API 返回和归档成功是三件事。Google 设置、权限、配额以及 ChatGPT 接入方式可能变化，操作时以文末官方链接为准。

克隆自己的仓库或 fork：

```powershell
git clone https://github.com/lj0014/fibitair-health-workflow.git
Set-Location fibitair-health-workflow
node --version
```

安装或用现有 Corepack 选择 pnpm 10.30.0。若没有配置 Corepack，可使用：

```powershell
npm install --global pnpm@10.30.0
pnpm --version
pnpm install --frozen-lockfile
```

`pnpm --version` 应为 `10.30.0`。不要在复现时删除锁文件或自动更新依赖。若不希望安装全局 pnpm，可把下文的 `pnpm` 替换为 `npx --yes pnpm@10.30.0`。

## 2. 先验证源码，不连接真实健康账号

```powershell
npm run typecheck
npm test
```

自动测试用的是合成数据、网络 mock 和本地 SQLite；通过不代表你的 Google 账号已经授权或设备产生了所有指标。

如要验证 Worker 能打包、本地数据库可建表，从模板生成**只供本地使用**的配置。模板的 `REPLACE_DATABASE_ID` 必须替换为格式合法的 UUID；本地测试也不能直接照抄占位字符串。

```powershell
if (Test-Path wrangler.local.toml) { throw '已有本地配置，请先检查，避免覆盖。' }
$localConfig = (Get-Content wrangler.workflow.toml.example -Raw).
  Replace('REPLACE_TOKENS_ID', ('1' * 32)).
  Replace('REPLACE_CACHE_ID', ('2' * 32)).
  Replace('REPLACE_OAUTH_ID', ('3' * 32)).
  Replace('REPLACE_DATABASE_ID', '00000000-0000-0000-0000-000000000001')
Set-Content -LiteralPath wrangler.local.toml -Value $localConfig -Encoding utf8
pnpm exec wrangler deploy --dry-run -c wrangler.local.toml
pnpm exec wrangler d1 migrations apply DB --local -c wrangler.local.toml
```

这里的 ID 全是测试值。`--dry-run` 仅打包，`--local` 仅应用本地迁移；不要将该配置用于云端部署或加 `--remote`。两份迁移 `0001_archive.sql`、`0002_oauth_attempts.sql` 都应完成。需要本地查看 `/health` 时，可运行 `npm run dev`；干净克隆中没有 Google 凭据，不能采集真实健康数据。

## 3. 创建 Google OAuth 客户端

在同一个 Google Cloud 项目中启用 **Google Health API**；需要周邮件时再启用 **Gmail API**。按 [Google Health 设置指南](https://developers.google.com/health/setup) 配置 Google Auth Platform / OAuth consent screen，个人测试通常选择 External 并把自己加入测试用户。

建议创建两个 **Web application** OAuth 客户端，分别用于 Health、Gmail，便于独立管理和撤销。它们使用相同的本地回调：

```text
http://127.0.0.1:8787/oauth/callback
```

这不是 Worker 的公网回调。授权脚本在你电脑上监听该地址，请保持终端运行，在同一电脑浏览器完成 Google 授权。若 8787 端口被本地 Worker 或其他程序占用，先停止相应进程。

下载客户端 JSON 到项目根目录，文件名为：

- `oauth-client-health.json`
- `oauth-client-gmail.json`（可选）

脚本要求 JSON 中有 `web.client_id` 与 `web.client_secret`；不要选成 Desktop app。上述文件均被 Git 忽略，不能上传到 GitHub 或粘贴到聊天。

Health 基本权限为：

```text
https://www.googleapis.com/auth/googlehealth.activity_and_fitness.readonly
https://www.googleapis.com/auth/googlehealth.health_metrics_and_measurements.readonly
https://www.googleapis.com/auth/googlehealth.sleep.readonly
```

Gmail 权限为：

```text
https://www.googleapis.com/auth/gmail.send
openid
https://www.googleapis.com/auth/userinfo.email
```

脚本使用 `openid email` 请求邮箱身份，并把收件人设为授权后验证通过的本人邮箱；它不申请读取收件箱。ChatGPT 如需用邮件补充近期活动背景，须通过你另行连接和授权的 Gmail 工具，不能由这里的 `gmail.send` 获得。

长期后台运行前，处理 OAuth 发布状态与验证要求：外部应用处于 Testing 且使用这类权限时，刷新令牌通常会在 7 天后过期。切换 In production 不等于通过 Google 品牌或权限验证，也不保证令牌永久有效。按控制台提示处理后重新授权，详见 [Google 令牌失效说明](https://developers.google.com/identity/protocols/oauth2#expiration)。

## 4. 创建 Cloudflare 资源并首次部署

```powershell
pnpm exec wrangler login
npm run workflow:setup -- provision
```

运行前确认 Wrangler 登录的是自己的 Cloudflare 账号。有多个账号时，应先按 Wrangler/Cloudflare 提示确定目标账号。模板默认 Worker 名为 `personal-health-workflow`；同一账号已有同名部署时，先核对并改模板中的 `name`，避免覆盖其他服务。自动脚本的资源名也固定，已有同名资源的账号应先核对，必要时走下一节手动恢复路径。

`provision` 按顺序完成：

1. 创建 **三个 KV**：`personal-health-tokens`、`personal-health-cache`、`personal-health-oauth`，分别绑定为 `TOKENS`、`CACHE`、`OAUTH_KV`。
2. 创建 D1 数据库 `personal-health-archive`，绑定为 `DB`。
3. 根据模板生成 `wrangler.workflow.toml`，写入你自己的资源 ID。
4. 对云端 D1 应用 `migrations/` 下的迁移，然后部署 `src/workflow/worker.ts`。
5. 生成并保存访问密钥到 `secrets/`，上传为 Cloudflare Secrets。

密钥职责如下：

| 本地文件 | 用途 |
|---|---|
| `secrets/ADMIN_TOKEN.txt` | 管理同步、导出、日程、邮件触发等接口 |
| `secrets/READ_TOKEN.txt` | Bearer 只读接口和 `/mcp` |
| `secrets/MCP_OWNER_KEY.txt` | 你在自己的 Worker 授权页批准 ChatGPT 连接时输入 |

三者不能互换。密钥不要填入 MCP URL，不要提交到 GitHub。初始化命令会保留格式正确的现有本地密钥，适合恢复中断，但不能当作轮换命令。

记下部署输出的真实 HTTPS 地址，然后修改生成配置中 `[vars]` 的 `PUBLIC_ORIGIN`：

```toml
[vars]
WEEKLY_EMAIL = "false"
PUBLIC_ORIGIN = "https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev"
```

`PUBLIC_ORIGIN` 必须是你实际访问的 HTTPS origin，不能有路径或结尾 `/`；若使用自定义域名，就填写实际使用的那个域名。它用于 OAuth 元数据和授权表单来源校验，未正确设置时 ChatGPT OAuth 不会工作。更新后重新部署：

```powershell
npm run deploy
```

`WEEKLY_EMAIL` 先保持 `false`，防止尚未核对数据便发送邮件。脚本不代你购买付费套餐；配额和费用按你当前 Cloudflare/Google 设置核对。

### 首次部署失败如何继续

首次账号尚未建立 `workers.dev` 子域名时，可能在部署处中断。若 `wrangler.workflow.toml` 已生成，先完成子域名设置，再继续：

```powershell
pnpm exec wrangler deploy -c wrangler.workflow.toml
npm run workflow:setup -- init-access
npm run workflow:setup -- init-mcp
```

`init-access` 只安装管理和只读令牌，`init-mcp` 单独安装 MCP 连接密钥，两个都要执行。然后按上节填写 `PUBLIC_ORIGIN` 并再次部署。

若在配置生成前中断，已创建的 KV/D1 不会自动回滚。先到 Cloudflare 控制台核对已存在资源，不要盲目反复运行 `provision`。仅在缺少资源时创建，例如：

```powershell
pnpm exec wrangler kv namespace create personal-health-tokens
pnpm exec wrangler kv namespace create personal-health-cache
pnpm exec wrangler kv namespace create personal-health-oauth
pnpm exec wrangler d1 create personal-health-archive
```

随后从模板复制到 `wrangler.workflow.toml`（不要覆盖已填写的配置），填入各自真实 ID、合法数据库 UUID 及自己的 `PUBLIC_ORIGIN`，再执行：

```powershell
pnpm exec wrangler d1 migrations apply DB --remote -c wrangler.workflow.toml
npm run deploy
npm run workflow:setup -- init-access
npm run workflow:setup -- init-mcp
```

不要把本地测试用假 ID 搬到云端配置。配置已经存在时，`provision` 会拒绝重新生成；这是保护已有配置的行为。

## 5. 分别授权 Health 与 Gmail

```powershell
npm run workflow:setup -- authorize health oauth-client-health.json
```

终端会给出 Google 授权链接，在本机浏览器打开，逐项确认请求的健康只读权限。脚本使用 state、PKCE、离线授权，检查 Google 返回的实际权限，并将 Health 令牌安装到 `TOKENS` KV。客户端 Secret 进入 Cloudflare Secrets；不会打印令牌内容。

需要周邮件时，再执行：

```powershell
npm run workflow:setup -- authorize gmail oauth-client-gmail.json
```

Gmail 凭据独立保存为 Secrets，收件人为已验证的本人邮箱。授权成功还不会发邮件，仍受 `WEEKLY_EMAIL` 开关控制。不需要 Gmail 时可以保持关闭，继续即时健康查询。

授权安装中断后重跑相同命令，脚本可能复用 `secrets/pending-*-oauth.json` 中尚有效的授权结果，完成上传后删除该临时文件。不要上传或分享 pending 文件。不要用 `legacy:setup:google`，那是参考项目的旧入口，且会输出令牌信息。

如果 Google 品牌配置需要首页/隐私页，当前 Worker 提供 `https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev/` 和 `/privacy`。公开页面不展示健康记录；页面存在也不代表完成 Google 验证。

## 6. 首次同步、核对数据

以下命令在项目根目录执行。日期按北京时间计算，首次同步最近 7 个自然日，含今天：

```powershell
$workerUrl = 'https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev'
$beijingNow = [DateTimeOffset]::UtcNow.ToOffset([TimeSpan]::FromHours(8))
$endDay = $beijingNow.ToString('yyyy-MM-dd')
$startDay = $beijingNow.AddDays(-6).ToString('yyyy-MM-dd')
./scripts/health.ps1 -Url $workerUrl -Action status
./scripts/health.ps1 -Url $workerUrl -Action sync -Start $startDay -End $endDay
./scripts/health.ps1 -Url $workerUrl -Action export -Start $startDay -End $endDay
```

脚本从本地 `secrets/ADMIN_TOKEN.txt` 读取凭据。导出在 `exports/`，含真实健康数据，必须留在自己的安全存储中。

检查同步返回的各指标状态和导出中的 `latestAttempts`、`fetched_at`、日期、`validDays`：

- `ok`：本次范围内取得该类记录，仍需核对日期和字段。
- `empty`：请求成功但没有记录，不能解释为零值，也不代表程序一定出错。
- `error`：该类采集失败，归档可能保留上次成功数据，不能称为本次刷新成功。
- `busy`：另一次同步占用采集锁，等它完成再重试。

对照手机里的睡眠日期/时长、步数、静息心率等。当天未结束，不能直接和完整日比较；设备未上传时，服务器不能强制补齐。设备或 Google 尚未生成的温度、血氧、HRV、VO₂ max 等允许为空。

查询最多 90 天，手动同步每次最多 7 天。需要过去 28 天基线时，分段回补且检查每段结果；只有数据真实可取才能形成基线。Google 分页预算、设备历史和 API 返回范围仍可能限制回补，不能用日历跨度替代有效样本数。

如当前网络需要已配置的代理，PowerShell 脚本可沿用简单系统代理，或明确传 `-Proxy http://127.0.0.1:你的端口`；它不会替你修改网络设置。Wrangler、Node 和浏览器的网络设置需分别确认，不能用浏览器能访问证明其他链路必然可用。

## 7. 在 ChatGPT 连接只读工具

依据 [OpenAI 自定义 MCP 接入说明](https://developers.openai.com/api/docs/guides/custom-mcp-server)，在网页端 Plugins / 应用入口添加自定义 MCP server。实际入口、账号资格和工作区限制以你的界面为准。

1. 名称可填 `fibitair`；URL 填 `https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev/live-mcp`。
2. 选择 OAuth。服务器支持动态客户端注册（DCR），通常不必手填客户端 ID/Secret；如界面提供可选栏位，留空。
3. 从 ChatGPT 发起连接，跳到你自己的 Worker 授权页后，核对地址与请求应用，输入本机 `secrets/MCP_OWNER_KEY.txt` 中的密钥并批准。不要把密钥发到聊天。
4. 返回 ChatGPT 后完成安装，在目标项目聊天中启用工具，再复制 [健康项目指令](健康项目指令.txt)。项目指令本身不会建立连接。
5. 首次明确问：「请调用 fibitair 的 `fetch_latest_health`，检查本次读取状态、数据截至日期和缺失项。」
6. 用同一账号在手机打开该项目，确认能选到工具并实际完成一次调用。网页连接成功不能替代手机端验收。

即时查询工具 `fetch_latest_health(days=7)` 每次先采集，再返回本次结果和数据包；检查 `refreshSucceeded`、`refreshStatus`、请求/完成时间和实际观测日期。历史工具 `health_packet(start,end)` 不会刷新 Google。

当前 OAuth 专门允许源码列出的 ChatGPT 回调，不是任意客户端都能接。其他支持 Bearer 的客户端可用 `/mcp` 和只读令牌；不要把管理令牌配给聊天客户端。没有自定义 MCP 功能时，仍可把自己的 JSON 导出上传 ChatGPT 分析，但应明确这是有日期的归档。

## 8. 核对后再开启周邮件

如果已完成 Gmail 授权并核对导出，将生成配置中的 `WEEKLY_EMAIL` 改为 `"true"`，然后执行 `npm run deploy`。默认调度是：

| 功能 | Cron（UTC） | 北京时间 |
|---|---|---|
| 定时回看最近 7 天 | `15 */6 * * *` | 每天 02:15、08:15、14:15、20:15 |
| 额外采集并处理上一完整周邮件 | `0 1 * * MON` | 每周一 09:00 |

周包是 JSON 数据包，不是自动生成的 GPT 报告，不会自动唤起 ChatGPT。Cron 更新传播可能需要时间。

需要立即验收发信时，可以用管理令牌显式调用 `POST /weekly-run`；这会向自己的 Gmail 发送上一完整自然周的数据包，仅在你明确准备发信时执行。它仍受开关和每周去重约束。`sent` 表示 Gmail API 接受发送，须另查收件箱/已发送才能确认展示；`needs_review` 或长时间 `sending` 时先检查邮箱，避免网络超时后重复发送。不要为重试随意删除去重记录。

## 9. 按层验收

| 层级 | 预期结果 | 未通过时先检查 |
|---|---|---|
| 干净源码 | 类型检查、自动测试、本地迁移、dry-run 通过 | Node/pnpm 版本、锁文件、D1 UUID 格式、两份迁移 |
| 服务存活 | `GET /health` 为 200 | 部署地址、网络；这项不证明健康采集成功 |
| 权限隔离 | 无凭据 `/export` 为 401；管理令牌能查 `/status` | 三类密钥是否混用、Secret 是否初始化 |
| Health 授权 | 首次同步不是所有指标 `error` | API 是否启用、返回 scopes、Google 令牌和设备/账户资格 |
| 数据真实有效 | 手机字段与导出对应，有效日期和缺失解释合理 | 手机同步、源端产数、字段语义、时区 |
| 后台续期 | 初始 access token 过期后仍可采集 | refresh token、Testing 状态、重新授权；初次成功不足以证明续期 |
| OAuth/MCP | 元数据 origin 正确、ChatGPT 调用真实工具 | `PUBLIC_ORIGIN`、`init-mcp`、安装/启用、账号/工作区权限 |
| 手机日常使用 | 手机项目内实际调用并显示本次读取时间 | 同一账号、工具可用性、是否仍只引用旧聊天 |
| 定时运行 | 后续 Cron 时段 `attempted_at` 自动更新 | 定时任务部署和传播、授权续期、API 配额 |
| 周邮件（可选） | Gmail API `sent`，本人邮箱确认收到 | Gmail API、本人授权邮箱、邮件开关、去重状态 |

一套可复现的验收记录应写下代码版本、环境版本、操作日期和每项状态；不应贴入真实健康数值、邮箱或令牌。可继续参考 [踩坑与排障](踩坑与排障.md)。

## 10. 日常使用与维护

日常按 [日常使用指南](日常使用指南.md) 在 ChatGPT 项目中直接提问；每次先让工具读取，再解释数据和已有背景。后台每周看看 `/status` 与数据包中的日期和有效天数，不能只看服务在线。

需要导入背景时，先修改 `examples/context.json` 的合成事项、日期，再运行：

```powershell
./scripts/health.ps1 -Url $workerUrl -Action context -ContextFile ./examples/context.json
```

相同 `id` 会更新，删除用管理接口 `DELETE /context/:id`。当前日程精度为天，没有自动日历同步或循环日程；计划不能当作已完成的活动。

设备同步时间为可选项：在 Google Data Access 添加 `https://www.googleapis.com/auth/googlehealth.settings.readonly`，执行 `npm run workflow:setup -- authorize health-device oauth-client-health.json`，确认原健康权限及新增权限都已批准，再在配置中加 `DEVICE_STATUS_ENABLED = "true"` 并部署。该命令替换 Health 授权，不能先开开关而沿用未获设置权限的令牌。最近同步时间也不能证明每个指标完整。

重新授权时重跑对应 `authorize` 命令；暂停邮件时把开关改回 `false` 并部署；暂停采集时移除 `crons` 并部署。更换公网域名需同步更新 `PUBLIC_ORIGIN`、部署和 ChatGPT 的连接地址，并重新核对 OAuth。

备份前建立 `exports/`，再使用 `pnpm exec wrangler d1 export DB --remote -c wrangler.workflow.toml --output exports/health-backup.sql`。备份含健康数据，应放在自己控制的安全存储；迁移到新数据库时先导入并验证，再切换绑定。

源代码公开不代表数据公开。`secrets/`、`exports/`、OAuth JSON、`.dev.vars`、本地/云端实际配置始终不应提交；推送前检查 `git status` 和待提交文件。Git 忽略规则不能清除已经提交的历史，误传凭据后应先撤销/轮换，再处理仓库历史。

删除整个个人实例时，先停采集与邮件，撤销 Google 连接，再清理自己创建的 Worker、D1、三个 KV 和本地敏感文件；另行处理 Gmail 和 ChatGPT 中的副本。删除数据库不会删除已发送的数据。
